# Mysic 项目 - Claude Code 执行规范

## 项目概述

本项目采用自动化长运行工作流，通过 Claude Code 实现从需求到可运行产品的全自动开发。

## 执行规范

### 任务领取规则

1. 从 `task.json` 中领取状态为 `pending` 的第一个任务
2. 检查任务的 `dependencies` 是否都已 `completed`
3. 如果依赖未满足，跳过该任务，领取下一个
4. 执行任务前，将状态更新为 `in_progress`
5. 执行完成后，更新状态为 `completed` 或 `failed`

### 任务执行规范

1. **代码规范**：遵循项目定义的代码风格
2. **测试规范**：每个功能模块需包含测试
3. **文档规范**：关键逻辑需添加注释
4. **提交规范**：每个任务完成后提交代码

### Git 提交规范

**重要规则**：每个任务完成后必须执行 git commit。

**提交流程**：
1. 任务执行完成并通过验证后
2. 执行 `git status` 查看变更文件
3. 执行 `git add <相关文件>` 添加变更
4. 执行 `git commit` 提交，提交信息格式：
   ```
   <type>(<scope>): <description>

   - 完成任务: <task_id> - <task_name>
   - 变更文件: <file_list>
   ```

**提交类型 (type)**：
- `feat`: 新功能
- `fix`: 修复 Bug
- `refactor`: 重构
- `test`: 测试相关
- `docs`: 文档
- `chore`: 构建/配置

**示例**：
```
feat(player): 实现音频播放服务

- 完成任务: task_2_2 - 实现音频播放服务
- 变更文件: lib/features/player/data/services/audio_player_service.dart
            test/audio_player_service_test.dart
```

### 进度记录规范

每次任务完成后，更新 `进度记录.md`：
- 记录完成的任务
- 记录创建/修改的文件
- 记录遇到的问题和解决方案
- 记录下一步计划

### 错误处理

1. 任务执行失败时，记录错误信息
2. 尝试自动修复，最多重试 3 次
3. 无法自动修复时，标记为 `blocked`，等待人工介入


## 权限说明

`run.sh` 使用 `--dangerously-skip-permissions` 参数运行 Claude Code，这意味着：
- Claude 将自动执行所有操作，无需人工确认
- 请确保在运行前已仔细检查任务列表
- 建议在隔离环境中运行

## 启动方式

```bash
# 1. 确认需求、技术选型、任务列表、依赖配置都已完成
# 2. 运行执行脚本
./.harness/run.sh

# 或者在 Claude Code 中直接执行
# 请开始执行 task.json 中的任务
```
